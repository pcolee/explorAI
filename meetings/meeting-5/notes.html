What is vibe coding?

2:07

"Vibe coding means describing an app in plain language and letting the AI write the code. The term comes from Andrej Karpathy, who described building software where you 'forget that the code even exists.'"

DoPress for the second note.

"But you still have a job. Google describes your role as prompter, guide, tester, and refiner."

"So how is that different from the coding you've heard about?"

7

Traditional vs. vibe coding

2:09

"Traditional coding: you write every line, you need to know the syntax, and you debug by reading code. Vibe coding: you describe what you want, you need to know what you want, and you debug by testing and describing the bug."

DoPress for the callout.

"One catch. The AI can tell you a feature works when it doesn't. That's the same hallucination problem from Meeting 2. So you test everything."

"Before we build anything, think back to two weeks ago."

Tips and tricks

15

Things to keep in mind

2:22

DoPress once per item. Each press lights that box with a soft glow.

"One: one change per message. If you ask for five things and it breaks, you won't know which one did it."

DoPress for number 2.

"Two: describe bugs like you'd tell a tutor. Not 'it's broken.' Say: 'When I click Next on the last card, the page goes blank. I expected it to loop back to card 1.'"

DoPress for number 3.

"Three: click every button. The AI can claim a feature works when it doesn't. You're the tester."

DoPress for number 4.

"Four: if the chat spirals, start fresh. Long, messy chats fill the context window with old mistakes. Open a new build and paste a clean summary."

DoOptional: read the handoff prompt below. It is also on the build sheet with a copy button. Tell them to read the result before pasting it, and to try restoring the previous version first.

Write a handoff so I can start a new build. Use Who, What, Why, How, and Looks to describe the app as it works right now. Then list what's broken, in one or two lines each. Don't include things we tried that didn't work.

DoPress for number 5.

"Five: no real secrets. No passwords, API keys, or personal info in an app you might share."

"Now, what are you going to build?"
